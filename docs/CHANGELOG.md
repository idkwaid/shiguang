# 更新日志

## v0.6.0（2026-11-25）

### 1. 修复“主图库仍包含子图库图片”（2620 张的问题）
- **根因**：分组节点的 DIRECT 扫描被实现成“最多向下 1 层”，结果把每个子文件夹里的图片也索引进了父图库（81 个子库 → 父库多出 2620 张）。
- **修复**：DIRECT 模式只扫**当前目录的直接文件**，不再进任何子目录。
- **自动校准**：打开分组图库时如果超过 30 秒未扫描，会在后台按新逻辑重扫；旧的错误条目会标记失效并清理（收藏除外），父库数量会恢复正常。
- 同时修正父库封面：封面指向已失效条目时自动回退到直接图片或子图库封面。

### 2. 子图库缩略图变快
- 打开任意图库时，会取消其他图库排队中的缩略图任务，把解码能力集中到当前图库，不用排在批量任务的队尾。
- 缩略图清晰度设置（v0.5.0）继续生效，默认低清。

### 3. 多选图库 / 图片
- **首页**：右上角「多选」进入选择模式，可批量**收藏 / 移动 / 删除**图库。
- **图库内**：右上角「多选」后可批量选择**图片**或**子图库**，执行收藏 / 移动 / 删除。
- 卡片会显示勾选状态；进入多选后点击即选中。

### 4. 移动与“应用到实际文件夹”
- 新增**设置 → 移动/删除应用到实际文件夹**（默认开启）：
  - 开启：图片移动使用系统 SAF `moveDocument` 真实移动文件；删除图片删除源文件；子图库移动/删除会尝试移动/删除真实文件夹。
  - 关闭：只调整 App 内索引/归属，不动手机文件；之后重新扫描可能恢复原位。
- 安全策略：**顶层图库永远不会被物理删除**（它对应你授权的整棵目录），只移除索引；压缩包内部文件始终只改索引。
- 图库移动只对**同一授权目录下的子图库**尝试物理移动；跨目录/根库移动仅调整 App 层级。

## v0.5.0（2026-11-25）

### 1. 缩略图清晰度可调（默认更快）
- 默认缩略图从 480px/82 降到 **256px/62**，大图库首轮缩略图明显更快、更省内存。
- 设置 → **缩略图清晰度**：流畅（低清 256）/ 均衡（中清 384）/ 清晰（高清 512）；
  切换后会清空旧缩略图并后台重新生成。
- 缩略图与 EXIF 分离；大图预览仍按原逻辑按需 1600px 解码，不受该设置影响。

### 2. 分组图库页改为“直接展示子图库卡片”
- 不再使用“顶部横向子图库条 + 下方照片”的布局。
- 打开一个分组图库：**子图库以网格卡片直接展示**（和照片网格同一套排布），点卡片进入子图库；父库自己的直接照片排在后面。
- 卡片右上角显示**该图库照片数量**，右下角是**图库收藏爱心**（首页卡片、子库卡片、收藏页一致）。
- 收藏页新增「收藏的图库」分区，与「收藏的图片」并列。

### 3. 修复双指放大时图片自动缩回
- 根因：旧版“双指长按 350ms 对比原图”的手势与捏合缩放冲突，缩放过程中手指稍微停住就触发对比、把图片重置为 1x。
- 已**移除双指长按对比**；现在双指移动/缩放只会更新缩放比例与位移，不会再被重置。

### 4. 数据迁移
- Room 升到 v4（`libraries.isFavorite`），带 3→4 迁移；升级不清数据。
- 旧缩略图文件保留，首次修改清晰度或触发重建后按新尺寸生成。

## v0.4.0（2026-11-25）

### 1. 分组导入改为“按目录树建层级图库”
- 选中 `/ben` 分组导入后：首页只出现一个 `ben` 图库；打开它，顶部是**子图库横向卡片**（如 `/ben/xxx/` 对应 `xxx`），下面是 `ben` 自己的直接图片。
- 子目录里的压缩包也作为子图库挂在对应目录下。
- 每个节点**只扫描自己的直接图片**，不再把子目录图片摊平到父级；父级容器没有图片时显示“这个图库只有子图库”。
- 封面：子库扫描完成后会向上回填父级容器封面。
- 数据库升级到 v3（新增 `parentId`、`scanMode`，带 2→3 迁移），侧载升级不清空已有数据。

### 2. 重复导入提示修正
- 同一文件夹已有顶层图库（整体或分组）时，分组导入会明确提示**已导入**，不再显示“没有发现图片/未扫描到”。
- 旧版“整体导入”的图库不会自动变成层级结构：长按移除（**不删源文件**）后重新分组导入即可。

### 3. 收藏爱心移到图片右下角
- 网格/瀑布流里每张图片右下角都有可点的爱心，直接收藏/取消收藏（不用再进长按菜单）。
- 搜索、收藏、标签详情页同样生效。

### 4. 首页/导航精简
- 删除「探索」页与底部「探索」Tab；底部只剩 图库 / 收藏 / 设置。
- 「标签」图标与「随机」图标移到首页右上角。
- 「智能清理」移到 **设置 → 智能清理**。
- 删除「那年今日」入口与页面。

### 5. 随机改为跟随当前图库
- 首页点随机：随机打开一个**顶层图库**。
- 在某个图库内点随机：只在**该图库的直接内容**里抽（直接图片 或 直接子图库），不会随机到 `/ben/xxx/` 里面的图片。
- 抽到子图库则进入子图库；抽到图片则全屏打开该图。

## v0.3.0（2026-11-23）

### 1. 修复“杀掉后台后所有图库都显示需授权”
- **根因**：导入时只在 `checkUriPermission` 判断为“无权限”时才调用 `takePersistableUriPermission`。
  但刚选完文件夹时系统给的是**临时授权**，检查结果是有权限 → 持久化授权从未写入 → 进程被杀后全部失效。
- **修复**：所有导入入口（整体/分组/压缩包/重新授权）现在**无条件**持久化授权；优先 READ|WRITE，失败回退只读，并把结果写入日志。
- **注意**：修复前已导入的图库不会自动恢复，需要重新选择一次文件夹（图库页「重新授权」或重新添加），之后杀进程不再丢失。

### 2. 新增运行日志
- 文件日志：`filesDir/logs/lumo.log`，单文件 1MB 轮转、保留 3 份；同时输出到 Logcat。
- 全局崩溃处理器：未捕获异常堆栈自动落盘。
- 应用内入口：**设置 → 运行日志**，支持刷新、分享、清空、长按复制。
- 覆盖关键链路：授权持久化、扫描开始/结束/失败、压缩包打开、缩略图解码失败、预览失败、导入结果。

### 3. 全屏查看器精简 + 底部滑杆
- 移除底部「幻灯片 / 缩略图 / 信息 / 编辑」按钮和顶部收藏/分享等控件。
- 单击画面中央：底部升起左右滑杆，可直接拖动跳到任意页；顶部保留当前页码。
- 保留：左右翻页、捏合缩放、双击缩放、双指长按对比原图、左边缘右滑返回、解码失败重试。
- 「编辑」「信息」移到图库网格的**长按菜单**；信息弹窗现在会读取 EXIF。

## v0.2.0（2026-11-23）

针对真机反馈的修复：

### 1. 缩略图 / 全屏预览全部“正在解码”
- **根因**：`Thumbnailer` 用 `BitmapFactory.decodeStream(stream, null, inJustDecodeBounds = true)` 的返回值判断成败。
  这个模式下 API 约定返回 `null`，导致每张图都被当成“读取失败”，缩略图和 1600px 预览全部为 null，UI 一直停在占位/“正在解码…”。
- **修复**：先打开流，再单独判断 `outWidth/outHeight`；新增 Robolectric 回归测试 `ThumbnailerTest`。
- **自动修复旧数据**：此前失败会把 `thumbReady` 标记为 1。现在打开图库/回到首页会检查“标记就绪但缩略图文件不存在”的条目，自动重置并重新生成；图库菜单也新增「重新生成缩略图」。
- **失败可见**：全屏解码失败不再是无限转圈，会显示“这张图片无法解码”并提供「重试」；网格里失败项显示破图图标。

### 2. 选中文件夹里的压缩包扫不到
- 旧逻辑只收集图片，完全忽略文件夹里的 `.zip/.rar/.7z`。
- 现在“添加文件夹”会弹导入方式选择：
  - **分组导入（推荐）**：文件夹里**每个压缩包**各建一个虚拟图库，**每个直接含图片的子目录**也各建一个图库；
  - **整体导入**：保持旧行为，整个文件夹一个图库、子目录平铺。
- 压缩包使用 SAF 子文档 URI 打开，不需要单独授权；ZIP/7Z 仍然不复制大文件。

### 3. 嵌套目录被摊平
- 分组导入会按目录结构拆成多个图库（名称用相对路径，如 `Gon/2024`），首页卡片分别展示。
- 数据库升级到 v2（新增 `treeRootRelPath` 列），带 `1 → 2` 迁移，不会清空已有图库。
- 扫描性能：分组导入先做一次目录结构摘要（只建“直接含图片”的目录），再顺序后台扫描；缩略图富化限制最多 2 个图库并发。

### 升级提示
- 旧版本“整体导入”的图库会保留；如果想按新结构看，可在首页长按该图库「从图库移除」（不删源文件），再重新用「分组导入」添加同一文件夹。
- 升级后首次打开图库会稍慢，因为旧条目的缩略图在自动重建。
