# 更新日志

## v0.2.0（2026-11-23）

针对真机反馈的修复：

### 1. 缩略图 / 全屏预览全部“正在解码”
- **根因**：`Thumbnailer` 用 `BitmapFactory.decodeStream(stream, null, inJustDecodeBounds = true)` 的返回值判断成败。
  这个模式下 API 约定返回 `null`，导致每张图都被当成“读取失败”，缩略图和 1600px 预览全部为 null，UI 一直停在占位/“正在解码…”。
- **修复**：先打开流，再单独判断 `outWidth/outHeight`；新增 Robolectric 回归测试 `ThumbnailerTest`。
- **自动修复旧数据**：此前失败会把 `thumbReady` 标记为 1。现在打开图库/回到首页会检查“标记就绪但缩略图文件不存在”的条目，自动重置并重新生成；图库菜单也新增「重新生成缩略图」。
- **失败可见**：全屏解码失败不再是无限转圈，会显示“这张图片无法解码”并提供「重试」；网格里失败项显示破图图标。

### 2. 选中文件夹里的压缩包扫不到
- 旧逻辑只收集图片，完全忽略文件夹里的 `.zip/.rar/.7z`。
- 现在“添加文件夹”会弹导入方式选择：
  - **分组导入（推荐）**：文件夹里**每个压缩包**各建一个虚拟图库，**每个直接含图片的子目录**也各建一个图库；
  - **整体导入**：保持旧行为，整个文件夹一个图库、子目录平铺。
- 压缩包使用 SAF 子文档 URI 打开，不需要单独授权；ZIP/7Z 仍然不复制大文件。

### 3. 嵌套目录被摊平
- 分组导入会按目录结构拆成多个图库（名称用相对路径，如 `Gon/2024`），首页卡片分别展示。
- 数据库升级到 v2（新增 `treeRootRelPath` 列），带 `1 → 2` 迁移，不会清空已有图库。
- 扫描性能：分组导入先做一次目录结构摘要（只建“直接含图片”的目录），再顺序后台扫描；缩略图富化限制最多 2 个图库并发。

### 升级提示
- 旧版本“整体导入”的图库会保留；如果想按新结构看，可在首页长按该图库「从图库移除」（不删源文件），再重新用「分组导入」添加同一文件夹。
- 升级后首次打开图库会稍慢，因为旧条目的缩略图在自动重建。
